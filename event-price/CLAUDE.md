# event-price — 감독 문서 1: 설계도

경조사(결혼·장례·돌잔치·상조) **가격비교 플랫폼**의 시제품. 가제 **"참가격"**(2026-08-24 사용자 지시). 이 가제는 한국소비자원의
등록 업무표장(42-0005997·42-0005998)이라 **공개 전에 반드시 바꾼다** — 이름은 `index.html`의 `APP_NAME` 상수 한 곳에만 있다.
다른 앱과 달리 **파이썬 수집기가 앞에 붙고**(fly-brain과 같은 구조) 문서 체계는 voxel-world·soccer와 같다. **이 문서가 루트 `CLAUDE.md`보다 우선**한다.
루트 규칙 중 유지: 한국어 UI·주석, `:root` CSS 변수, 폰트 스택 `'Segoe UI', Pretendard, sans-serif`, 마우스/키보드 + 터치 양쪽 경로, `store` 래퍼(키 접두사 `ep_`),
`file://` 동작, 전역 노출 없음(IIFE 하나), 상태 변경 시 전체 재렌더.

## 1. 범위

**목표**: 정부가 공개한 경조사 가격(소비자원 참가격 결혼서비스, 보건복지부 e하늘 장례)을 한 화면에서 비교하고, 사용자가 받은 견적이 그 분포 안에서 어디쯤인지 보여 준다.
장례는 품목 단가로 **시나리오 총액**(일수·빈소 규모·조문객·제단·도우미·관·수의)을 계산해 시설끼리 비교한다. 돌잔치처럼 공개 가격이 없는 분야는 견적 비교 계산기만 둔다.

**범위 밖** (이유): 타사 플랫폼(웨딩북·네이버 플레이스 등) 크롤링(DB제작자권·부정경쟁) · 지도 API 결과 저장(약관) · 카페 글 복제(저작권) · 대표자 성명 등 개인정보 저장 ·
"최저가" 같은 단정 표현(표시광고법) · 수익화(휴직 중 금지, 복직 2026-12-01 후 겸직허가 선행).

**법적 경계**: e하늘 자료는 저작권정책상 **수익 목적 이용 시 보건복지부 사전 허락**이 필요하다(시제품 단계에서는 허락 전). 참가격은 정책 문구가 없어 소비자원에 문의한다.
두 기관 이름은 **출처 표시로만** 쓴다. 화면 어디에도 "소비자원이 운영" 같은 오인 표현을 두지 않는다(푸터에 무관 고지).

## 2. 기술 결정 — 바꾸려면 이 문서를 먼저 고친다

- **앱** = `index.html` 하나. 해시 라우팅(`#home` `#wedding` `#funeral` `#dol` `#quotes`), 뷰 함수가 HTML 문자열을 만들고 `#app`에 통째로 넣는다. 이벤트는 `#app`에 위임(`data-action`).
  입력값은 **`change` 시점**에만 상태에 반영한다(타이핑 중 재렌더로 포커스를 잃지 않게). 검색창은 엔터로도 반영.
- **앱 셸(모바일 앱 형식, 2026-08-24 사용자 지시)**: 세로 단일 컬럼(최대 폭 600px, 데스크톱에서도 같은 모양), 상단 바(브랜드+현재 화면명),
  **하단 고정 탭 바 5개**(`#tabs`, safe-area 대응). 목록은 표가 아니라 **카드**(`.fcard` 장례식장 — 누르면 산출 내역 펼침, `.bcard` 업체 — 60개씩 + 더 보기).
  넓은 표는 상세 안 `.scroller`에서만 가로 스크롤. 확인 기준: 375px에서 5개 화면 모두 `scrollWidth == clientWidth`.
- **PWA**(particle-playground 관례): `manifest.webmanifest`(standalone·portrait, 아이콘 ₩ — 이름이 가제라 글자 대신 기호),
  `sw.js` — 껍데기는 캐시 우선, **`index.html`은 네트워크 우선**(데이터가 인라인이라 캐시 우선이면 갱신이 안 보임; 오프라인일 때만 캐시).
  등록은 http(s)에서만, `file://`는 서비스 워커 없이 그대로 동작. 데이터를 다시 주입해도 sw 버전은 안 올려도 되지만, **sw.js 자체를 고치면 `CACHE` 버전을 올린다**.
- **데이터** = `<script id="ep-data" type="application/json">` 블록. `build_data.py`가 채운다(`fetch` 없음 → `file://`에서도 동작). 원본 JSON은 `data/`에도 남긴다.
- **수집기** = `build_data.py`(파이썬 3.10, `requests`만 사용). 공공 사이트의 **화면이 쓰는 JSON/HTML 호출**만 쓰고 파일 다운로드(엑셀)는 하지 않는다.
  - 참가격은 인증서 체인이 불완전해 그 호스트만 `verify=False`. 두 사이트 모두 **세션 쿠키가 있어야 AJAX가 응답**하므로 화면을 먼저 한 번 연다(`warm_up`).
  - 참가격 분위 API는 품목×지역 조합당 약 1초가 걸린다(전체 98품목 × 14지역 × 6분위 ≈ 10분). 요청은 (카테고리, 필수/선택) 단위로 쪼개고 타임아웃 240초.
  - e하늘은 기본 `--sido 서울특별시`. `--all`(전국 1,083곳)은 보건복지부 허락 후에만.
- **저장**: `store`로 `ep_region`(비교 지역), `ep_wedding_quick`(내 견적 위치 입력), `ep_funeral_scenario`(장례 시나리오+필터), `ep_dol`(돌잔치 견적 배열), `ep_quotes`(결혼 견적 배열). 서버 없음.
- **서버·DB·업체 등록 수신은 8단계**(복직·겸직허가 후). 그 전까지는 정적 파일만.

## 4. 계산 규칙 (정본은 `index.html`의 `scenario()`·`quoteTotal()`·`dolTotal()`)

- **결혼 "내 견적 위치"**: 값이 분위점(p10·p25·median·p75·p90) 사이 어디인지 선형 보간해 0~100 백분위로 근사. 자료가 2점 미만이면 비교 불가.
- **결혼 견적 비교**: 합계 = 필수 5항목(대관, 1인 식대 × 보증 인원, 스튜디오, 드레스, 메이크업) + 체크한 추가금. 비교 기준 = 같은 구성의 **지역 중간가**(중간가 없는 항목은 입력값 그대로).
- **장례 시나리오** 구성 요소와 선택 규칙: 빈소(선택 규모 안에서 **중간 가격**의 방 × 일수, 면적은 품명의 `㎡`에서 파싱) · 안치(최저 × 일수) · 염습(주간 최저) · 제단 꽃장식(등급 하=최저, 중=중간, 상=상위 25%) ·
  도우미(기본 품목 × 명 × 일수) · 청소(최저 × 일수) · 관·수의(최저 또는 중간) · **식사 = 조문객 × 1인 예산(가정)**. 미등록 항목은 0으로 두고 표시한다. 전국 평균 총액은 같은 규칙을 `funeral_benchmarks`에 적용.
- **돌잔치**: (1인 식대 + 답례품) × 보증 인원 × (1 + 주말 할증) + 대관 + 돌상 + 스냅 + 사회.

## 5. 검증 방법

`python -m http.server 8765`(루트) → `http://localhost:8765/event-price/`, 그리고 `file://`로 직접 열기. 콘솔 에러 0, 각 탭 조작(지역 바꾸기, 견적 입력, 장례 시나리오 변경·행 열기, 돌잔치 추가/삭제, 인쇄).
수치 검증은 화면 값과 `data/*.json`·원본 사이트 화면을 **같은 시설·같은 품목으로 대조**한다(예: 서울아산병원 빈소 561㎡ 4,890,000원).
