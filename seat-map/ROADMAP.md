# ROADMAP — 앉을 자리

사양서 9장의 마일스톤에 **완료 조건**을 붙인 것. 조건은 실측값으로만 체크하고,
**조건을 낮춰서 통과시키지 않는다.** 한 세션에 한 단계.

---

**2026-09-04: 인증키 없이 받을 수 있는 파일 데이터로 실측이 들어왔다**(DECISIONS.md D-17).

남은 키 의존은 **T-DATA(분산)와 실시간**뿐이다. 그동안 M2-2(경로 탐색)를 진행할 수 있다.

**해결해야 할 것**: 실측을 넣자 사양서 10장 세 줄이 어긋났다(D-19·D-20). 모델 결함이 아니라

## M3 — 웹 UI  (뼈대 완료, 다듬기 남음)

사양서 7장 전체. **대문 없이 바로 검색 화면**(2.2).

2026-09-04: `index.html` 이 길찾기 네 화면(출발·도착 → 언제 → 경로 목록 → 상세)으로 돈다.
남은 것: **지도**(7.6), 장소 등록(7.4), 「앉으셨나요?」 버튼(M4).

완료 조건:
- 출발지 입력 → 경로 목록 → 상세까지 마우스·키보드·터치 세 경로 모두 동작
- 버튼 높이 52px 이상(주요 64px), 본문 17px 이상, 「큰 글씨」 토글이 `store`에 저장됨
- 좌석 배치도가 **실제 좌석 수만큼** 격자를 그린다(지하철 54, 시내 23, 마을 15, 광역 41)
- 색 배지마다 문구가 함께 나온다. 색을 흑백으로 만들어도 읽힌다
- 보간값에 출처 문구가 붙는다
- `file://`로 열어도 동작한다

## M4 — 피드백 루프

「앉으셨나요? 예/아니오」 수집 → α 학습 → 노선별 보정치.

**후순위로 미루지 않는다**(사양서 5.3·11장). 이것이 복제 못 하는 자산이다.

완료 조건:
- 하차 시점에 버튼 하나가 뜨고, 응답이 기기 안에 쌓인다
- 노선·시간대·요일별 α 추정이 돌고, 표본이 적으면 기본값 0.55로 물러난다
- 학습된 α가 실제 정렬을 바꾸는 것을 한 사례로 보인다

## M5 — PWA / APK

`manifest.webmanifest` + 서비스워커, WebView 래퍼(`android-*` 폴더들과 같은 방식).

완료 조건:
- 비행기 모드에서 등록한 장소 주변 경로 탐색이 된다
- 홈 화면 추가가 되고 아이콘이 뜬다
- APK가 `file:///android_asset/index.html`로 같은 코드를 돌린다
